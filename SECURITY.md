# Security policy

## Reporting

Не открывай публичный issue с cookies, прокси, API-ключами или ngrok-токеном.
Используй GitHub private vulnerability reporting / Security Advisories.

В отчёте укажи:

- версию/коммит;
- шаги воспроизведения;
- impact;
- минимальный PoC без реальных секретов.

## Секреты

В репозиторий **не должны** попадать:

- `.env`;
- `accounts*.jsonl`, cookies, email-файлы;
- прокси с логином/паролем;
- `data/jobs.sqlite3`;
- `data/output/*`;
- `NGROK_AUTHTOKEN`;
- `API_KEY` / `API_KEYS` / `WEBHOOK_SECRET`.

Если секрет попал в git — отзови его и перевыпусти. Удаления файла
недостаточно: значение остаётся в истории.

## Развёртывание

- Держи `BIND_HOST=127.0.0.1`, пока не нужен внешний доступ.
- Для публичного доступа ставь `API_KEY` или `API_KEYS`.
- `WEBHOOK_SECRET` обязателен, если разрешён внешний webhook.
- ngrok терминирует TLS и видит тела запросов; используй только свои
  аккаунты и доверенный туннель.
- Docker-порт публикуй осознанно; не открывай его в интернет без ключа.
- Не запускай `ALLOW_NO_PROXY=1` и `ALLOW_SHARED_PROXY_TEST=1` в проде.

## Данные аккаунтов

Cookies дают доступ к аккаунту. Не передавай их третьим лицам, не
публикуй в issue и не используй чужие аккаунты.

## Поддерживаемые версии

Только текущая ветка `main`. Старые форки/сборки не поддерживаются.
